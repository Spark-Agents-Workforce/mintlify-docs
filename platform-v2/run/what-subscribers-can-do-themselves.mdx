These switches, **Customer portal features** on **Settings > Branding**, drive the portal-versus-admin table on [When a subscriber asks for help](/platform-v2/run/when-a-subscriber-asks). Every switch left on is a request that answers itself.

<Steps>
  <Step title="Know the switches">
    - Turning a switch off hides that action everywhere in the portal. Eight start on, two start off:

    | Switch | What subscribers can do when it's on |
    | --- | --- |
    | **Ship Now** | Bill and ship their next order immediately |
    | **Merge subscriptions** | Combine two or more active subscriptions into one |
    | **Delay next order** | Push back the next order date by a preset you offer |
    | **Change delivery frequency** | Switch to a different delivery schedule |
    | **Change order date** | Pick a different next order date from the calendar |
    | **Pause subscription** | Accept a pause when the cancellation flow offers one (the flow is its only surface; there is no separate pause button) |
    | **Reactivate subscription** | Restart a cancelled subscription from the account area |
    | **Discount codes** | Apply a discount code from the order summary |
    | **Discount code stacking** *(off by default; appears only while Discount codes is on)* | Apply more than one code to the same subscription |
    | **Dashboard FAQ block** *(off by default)* | See a short FAQ block on their dashboard (once you add content) |

    <Check>
    **Checkpoint:** the on/off pattern matches the self-service you want.
    </Check>

    <Frame>
      <img src="/images/platform-v2/run/31-portal-features.png" alt="Customer portal features on Settings > Branding: the switches, with delay options and quantity limits inline." width="480" />
    </Frame>
  </Step>
  <Step title="Set the limits under them">
    - The limits live inline under their switches: **Delay options** (defaults 7, 14, 21, 28 days; **Add another option** for up to eight, each 1 to 365), **Maximum days in advance** under the order-date switch, **Maximum stacked discounts** (1 to 20, blank for no limit) under the stacking switch, and **Maximum quantity per item** (default 30).
    - The delay options are also used by delay offers in the cancellation flow.
    - The quantity cap is enforced on the server and stops raises only; a line already over a lowered cap stays as it is. The other limits shape what the portal offers, not server locks.

    <Check>
    **Checkpoint:** each preset and cap is a number you're happy to let subscribers pick.
    </Check>
  </Step>
  <Step title="Know the two side effects">
    - Save offers pass through these same switches: a pause offer never shows while pausing is off ([When a save offer doesn't show](/platform-v2/run/when-a-save-offer-doesnt-show)).
    - Already-paused subscribers can always resume from their portal; resuming has no switch.

    <Check>
    **Checkpoint:** nothing switched off is still promised by your cancellation flow.
    </Check>
  </Step>
</Steps>

<Note>
**These are preference gates, not locks.** They shape what the portal offers, not a security boundary. Doing it for a subscriber: [When a subscriber asks for help](/platform-v2/run/when-a-subscriber-asks).
</Note>
