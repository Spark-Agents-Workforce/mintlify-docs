<span className="os-chip">15 min</span>

**Bulk operations** in the left nav lists your runs; **New bulk operation** opens the builder (the **Bulk operation** button on the Subscriptions list jumps straight there).

<Tip>
**A handful of rows doesn't need a builder.** Tick them on the Subscriptions list and an action bar appears: **Change status**, **Change frequency**, **Change next billing date**.
</Tip>

<Steps>
  <Step title="Build the audience">
    - Open **Bulk operations**, click **New bulk operation**, and name the run.
    - Under **1. Audience**, one condition is preset: **Subscription status** is **Active**. Change or delete it for a wider audience.
    - **Add condition** stacks filters: billing date, contained products, frequency, shipping country, migration origin, customer tags, and more. **Add condition group** mixes "all of these" with "any of these": one level of grouping.
    - The estimate updates as you build, with a per-status breakdown; **View sample** opens recent matches (each has **Exclude**), and **Download CSV** saves the list.

    <Check>
    **Checkpoint:** everyone on the CSV should get this change.
    </Check>

    <Frame>
      <img src="/images/platform-v2/run/10-bulk-audience.png" alt="The bulk builder: status and product conditions stacked, the live estimate counting the matched audience." width="560" />
    </Frame>

    <Note>
    **The estimate is live, not locked.** The audience is re-evaluated when the run starts, so the count can drift between now and then.
    </Note>
  </Step>
  <Step title="Stack the actions">
    - Under **2. Actions**, add up to four from the **Add an action** menu, in three groups.

    | Group | Actions |
    | --- | --- |
    | Subscription | **Delay billing** · **Change interval** · **Add discount** · **Pause subscription** · **Cancel subscription** · and more |
    | Products | **Swap product variant** · **Update product price** · **Remove product** · and more |
    | Customers | **Add customer tag** · **Remove customer tag** |

    - The Products actions target one **variant**, not a whole product: one action per variant.
    - Actions run in order on each subscription; if one fails, the rest are skipped for that subscription only. Reorder with the arrows.
    - A warning banner names any matched status an action can't touch: skipped, not failed.
    - Under **3. Options**: **Don't send customer notifications for these changes** keeps the run silent. **Schedule for later** books a date and time in your store's timezone. **Treat skipped subscriptions as failures in the run report** marks the run **Completed with errors** when anything was skipped; the rows still read Skipped, and **Retry failed** doesn't re-run them.

    <Check>
    **Checkpoint:** four actions or fewer, in the order you mean them.
    </Check>

    <Frame>
      <img src="/images/platform-v2/run/11-actions-stack.png" alt="The actions stack: ordered steps, the add-action picker, and the three run options." width="560" />
    </Frame>
  </Step>
  <Step title="Run and watch">
    - Click **Run operation**; the confirm restates the count, breakdown, and actions. **Run now** starts it (**Save & schedule** books it if you set a date).
    - Filter results by status (All, Succeeded, Failed, Skipped, Pending). **Pause** and **Resume** mid-run; **Cancel** stops the rest: processed subscriptions keep their changes, and a cancelled run can't resume.
    - When it finishes, **Retry failed** re-runs only the failures; **Download results CSV** saves the receipt.
    - A run that fails outright opens a **Bulk operation failed** alert on **Settings > Operational health** ([When an alert opens](/platform-v2/run/when-an-alert-opens)).

    <Check>
    **Checkpoint:** no row left Pending; failures retried or explained.
    </Check>

    <Frame>
      <img src="/images/platform-v2/run/12-bulk-run-report.png" alt="The run report: completed, with per-subscription results and the results CSV." width="640" />
    </Frame>
  </Step>
</Steps>
